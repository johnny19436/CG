2. GPU 互動視覺化（約 2.5 分鐘）
  

【口播 — 設定說明 / 4 dye】

一開始保持在 `4 dye`。目前顯示的 dye 是 passive tracer，只用來視覺化流動；它會隨速度場被搬運，但不會反過來影響速度或壓力。紫色、深藍代表較低染料濃度，黃橘代表較高濃度。

程式每一步都會在中心附近加入固定的 Gaussian 外力，同時加入染料來源，所以即使不碰滑鼠，畫面中的流體也會持續被推動。

模擬主要在 CUDA 上執行，顯示則透過 CUDA-OpenGL PBO 互操作完成，所以不需要每幀把整張格點資料複製回 CPU。

【口播 + 動作 — 1 / 2 / 3 欄位切換】

接著切到 `1 velocity magnitude`。
這個畫面顯示速度大小，也就是流體在各位置移動得快不快，不顯示方向。這裡使用的是熱度圖，偏藍代表速度較小，綠色到黃橘代表速度較大。因為固定外力往右推，所以中心附近會有比較亮的高速區，然後被 advection 和黏滯擴散拉開、抹平。

再切到 `2 pressure`。

  

Pressure 是 projection 步驟解出來的壓力場，用來修正速度，讓流體更接近不可壓縮。每一步解 pressure 前會先從 0 開始，解出來的相對壓力可能是正也可能是負；視覺化時藍色代表負值，綠色代表接近 0，橘紅色代表正值。

因為固定外力主要往右推，速度場會產生向右的流動。Projection 會解出一個相對的壓力修正場，讓右側壓力偏高、左側壓力偏低，形成由左到右的 pressure gradient。接著程式用 `velocity -= grad(pressure)` 修正速度，抵消多餘的壓縮或膨脹，讓流體更接近不可壓縮。

  

最後切到 `3 divergence`。

  

Divergence 可以看局部流體是不是在膨脹或壓縮。它同樣使用以 0 為中心的顏色映射：藍色代表負值，綠色代表接近 0，橘紅色代表正值。

固定外力往右推時，中心附近的速度會往右增加。從局部來看，左側比較像流體被帶走、往外散開，所以 divergence 可能偏正；右側比較像流體被推過來、產生壓縮，所以 divergence 可能偏負。因此 divergence 的左右顏色常會和 pressure 看起來相反。Projection 之後，divergence 應該盡量接近 0，也就是畫面應該大部分接近綠色。

  

【口播 + 動作 — 滑鼠互動】

最後切回 `4 dye`，示範滑鼠互動。

（左鍵拖曳 5～8 秒）

3. CPU 與 GPU 對比（約 1.5～2 分鐘）

================================================================================

  

【口播 — 過場】

接下來我加重負載來比較 CPU 和 GPU 的 frame rate。

  

這裡我會把 `--vsync` 設成 `0`，也就是關掉垂直同步，避免 FPS 被螢幕刷新率限制住。這樣終端機顯示的 FPS 才比較能反映 CPU 和 GPU backend 本身的運算差距。

  

這次使用 `512 x 512` 的網格，每一幀連續跑 `16` 個物理步，也就是 `--steps-per-frame 16`，而且每一步都做 `80` 次壓力 Jacobi 迭代。

  

我會先跑 CPU backend，接著用完全相同的參數切到 GPU，只改 `--backend`。

  

【指令 — CPU】

```bash

./build/fluid_sim visualize --backend cpu --width 512 --height 512 --iters 80 \

  --dt 0.1 --steps-per-frame 16 --field dye --vsync 0

```

  

【口播 + 動作】

現在標題顯示的是 CPU backend。

  

這個設定下，每一幀要連算 16 個 simulation steps；每一步裡面又包含 80 次壓力 Jacobi 迭代，所以總計算量很高。

  

另外 CPU backend 還需要在 host 端把場資料轉成顏色，再上傳給 OpenGL 顯示，因此整體負擔會更重。

  

（左鍵拖曳 6～8 秒）

  

可以看到滑鼠攪動時反應比較遲鈍，畫面也比較容易卡頓。

  

（指終端機）

  

這時候可以觀察終端機上的 CPU FPS，作為後面 GPU 對比的基準。

  

（Esc）

  

【口播】

接下來使用完全相同的參數，只把 backend 從 `cpu` 改成 `gpu`。

  

【指令 — GPU】

```bash

./build/fluid_sim visualize --backend gpu --width 512 --height 512 --iters 80 \

  --dt 0.1 --steps-per-frame 16 --field dye --vsync 0

```

  

【口播 + 動作】

現在換成 GPU backend。

  

參數沒有改，一樣是 `512 x 512`、每幀 16 個物理步、每步 80 次 Jacobi 迭代。

  

差別是模擬主要留在 GPU 上執行，每個 CUDA kernel 會讓大量 grid cells 並行更新。

  

（同樣左鍵拖曳 6～8 秒）

  

可以觀察到 GPU backend 的反應通常會比 CPU backend 更順，滑鼠攪動也比較跟得上。

  

這裡展示的是同一套 Stable Fluids 物理流程，但 CPU 和 GPU 的執行模型不同，因此效能表現會有差距。

  

（Esc）
